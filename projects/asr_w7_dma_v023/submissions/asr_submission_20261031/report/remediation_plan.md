# 当前版本整改方案与验收条件

## 结论与冻结范围

冻结W7p8/A16/C48数值合同、16×16物理阵列与32×32逻辑分块。整改优先处理结果收集、打包反压和调度衔接。当前Roofline橙点为局部RTL矩阵测试，不代表整机ASR。其吞吐45.14 OP/周期，低于相同强度下146.29 OP/周期的接口理论屋顶；现有执行效率仍有较大改善空间。

## 证据与问题清单

| 观测 | 已确认事实 | 尚需验证的原因 |
|---|---|---|
| 整体点位 | I=9.1429 OP/B，P=45.1402 OP/周期 | 理论屋顶下的差距由多种开销构成 |
| 结果收集阶段 | 5242/8711周期，约60.18% | 分解段命令、packer反压、缓存响应、提交与尾部等待 |
| 计算阶段 | FSM为1632周期，约18.73% | 不等于逐PE有效MAC周期，需新增观测 |
| 打包器 | backpressure状态3554周期，约40.80% | 与收集等待的交集及阻塞链；两种比例不能相加 |
| 权重搬运 | K96记录累计6144 B，唯一区域3072 B | 缓存驻留及不同输出块复用生命周期 |
| 外层执行 | 集成小链路各引擎顺序执行 | 依据依赖与块粒度检查可并行范围 |

源码已经有A/W双缓冲、下一K块预取和II=1的C收集提交路径。不能把“增加双缓冲”或“把收集改成II=1”当成尚不存在的新设计。需要确认这些能力在下游反压和控制条件下为何没有转化为持续吞吐。

## R0 补齐观测并建立唯一基线

在同一时钟域只读采集：每PE有效乘加事件、阵列清零和排空、COLLECT的seg_needed/cseg_ready/commit_now/cval_valid/cval_ready、缓存读写握手、结果FIFO占用、DMA读写握手及B响应。以任务ID、块坐标与K分块关联事件，不改变ready/valid和数值逻辑。

首个基线固定M64 N32 K96 CVALID=1、原始positions/clip、PIPE=4、原BFM延迟/反压/种子。以输入、源码、配置和gold哈希固定版本。保留CVALID=0的复用A/B作为另一组同条件试验，不能跨组求加速比。

验收：所有状态分类之和等于8711窗口或明确的新窗口；总字节对账；给出有效MAC、读算/算写交集，以及未分类时间。不得以busy代替计算。

## R1 解除结果收集与打包写回的直接耦合

现有COLLECT在seg_needed未接受或packer反压时保持pipe寄存器，并停止后续组推进。先记录各阻塞分支占时与因果交集，找出持续阻塞源。

候选改法是保留现有192位、每次4个C48的收集流水，在其后加入带地址、块ID、last和错误标志的弹性结果队列，或复用结果存储实现隔离。收集仅在队列满时反压；打包器独立把192位组组织为128位AXI拍。容量由最坏已接受突发及响应延迟推算，不任意宣布只需几个寄存器。

同时检查6拍小段命令的发射间隙。在地址连续、INCR、4KiB边界与数值格式允许时合并段，保留尾拍WSTRB和顺序。C缓存写回不能因发送队列改变而丢失、重复或越过跨K依赖。

验收：逐元素输出一致，字节与地址访问一致或有明确减少原因；收集阻塞与打包器反压分别下降；同条件总周期下降；提供新增FIFO/控制逻辑的真实综合资源对比。尚无综合结果时只列源级容量。

## R2 让已有预取与结果处理持续运行

检查stage_a_ready与stage_w_ready、stage_release和bank覆盖保护，让下一K块预取与当前计算实际重叠。A/W生命周期分离，已存在的权重驻留候选先按原始A/B重现，再处理奇数M尾块与跨K部分和并集成。

结果收集、下一块计算和前一块写回可在无真实依赖且缓冲允许时交叠。若只有一套PE累加寄存器，必须先完成该块结果的安全快照，不能为了交叠提前清零。写响应延迟应留在独立的提交/排空状态，正常DONE依然等待所有B响应。

验收：输出一致，无bank读写冲突；A/W/C版本与区域可追踪；真实有效MAC与DMA交集增加，完整任务周期下降。双缓冲模块存在、prefetch计数增加都不能单独作为验收。

有用运算数除以阵列理论峰值为768周期，而FSM计算阶段为1632周期；还需分离阵列填充、排空及K块/象限切换开销。缩短这些开销前，必须证明累加次序、clip、溢出检查和部分和生命周期保持一致。

## R3 核验图级融合与软硬件分工

统一V024已经包含显式条件下C48到A16融合。先检查它与固定数值合同、消费者布局和逐列scale/bias的对应，不把另一版本候选直接并入当前性能轨迹。兼容时减少中间DDR写回与重读，其他情况回退。

对数据重排，先区分哪些是模型必需变换、哪些是输入打包开销。可在主机一次准备的格式转换前置，但完整运行时间必须包含电脑端新增开销。批处理和音频断句作为独立主机策略评估延迟与吞吐，不混入矩阵小测结果。

## 决策顺序与停止条件

先完成R0，再依据占时确定R1优先级，然后开展R2，最后评估R3。每步保留独立分支、固定gold及同条件A/B。任何输出不一致、地址/版本错误、写响应未排空、收益只来自缩短计时窗口的候选均不能合入。

此时不承诺新的速度倍数。要先证明点向右或向上移动，再给出新Roofline；带宽屋顶本身只有接口变化或独立持续带宽测量支持时才可改变。
