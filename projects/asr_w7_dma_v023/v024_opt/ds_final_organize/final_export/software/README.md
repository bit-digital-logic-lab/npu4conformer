# Host / software boundary

This folder documents the host-side operations that remain outside the PL.
It is **not** a complete host executor and does not contain any missing model
asset.

## What the host does once, before START

1. Load the input tensor(s) and weights into the DDR arena / parameter window.
2. Build and write the WCPG v2 plan (header + 192 B nodes + payloads).
3. Preload the 64-word per-channel scale/bias table (32 scale + 32 bias) while
   the epilogue is drained.
4. Program `plan_base`, `plan_count`, then write `1` to CSR `0x10` (START).
5. Poll `0x04` for `done/fault` and read the terminal state (`0x1C`, `0xB0`,
   `0xB4`/`0xB8`/`0xBC`, `0xC4`).

After START the PL controller fetches descriptors and drives matrix / vector /
layout / DMA autonomously. The PS CPU is not in the per-operator loop.

## What is not implemented

- No complete 512-dim ASR host executor, ONNX importer or WER/CER runner.
- No sealed-payload re-lowering for the full 591-tensor DAG.
- No per-tile table DMA; the table is a one-time preload in this candidate.
- No board driver, VNC, MIG/HP topology or DDR PHY model.
- No claim that the PS hard DDR controller is bypassed. The logic BFM is an
  independent AXI slave; the physical board path is still PS hard DDR.

## Files

- `CSR_MAP.md` — human-readable CSR map.
- `csr_map.h` — C constants for the CSR offsets and terminal bits.

The small-graph plan/fixtures are generated by
`scripts/sim/gen_v024_graph.py`; they are test fixtures, not the full model.
