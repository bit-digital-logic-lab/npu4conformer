# 多智能体协同与反馈闭环

GPT负责拆分任务、固定验收条件和最终整合；DeepSeek与Gemini 3.8 Flash并行完成独立子任务；Gemini 4 Argon与Claude独立复核相同候选版本。测试失败、评审问题或证据缺失回到GPT，由其决定返工与重分发。只有相同版本的必要检查全部通过才进入交付。

## 任务与版本合同

分发前固定输入、数值合同、允许修改的文件、输出路径、验收命令和轮次上限。不同实现者使用隔离分支或工作目录，避免互相覆盖。候选交给验证者时冻结源码SHA与输入哈希；评审必须指向该版本，任何实现变更都使旧评审失效。

验证者读取原始需求、候选差异、测试日志和测量口径，不能仅复述实现者总结。发现数值、接口、范围或资源证据问题时，返回可定位的问题、复现方式和修复条件。模型共识不代替RTL、数值对照、综合或板测。

## 钩子与自动化位置

以下为本项目的钩子设计，尚未接入常驻服务或外部模型API。

- task_started：登记任务、版本、工作目录、验收条件及预算。
- artifact_ready：冻结候选SHA，触发确定性测试，并将相同快照交给独立验证者。
- test_finished与review_finished：汇集退出码、结构化问题与证据路径；缺记录保持待验证。
- revision_required：把失败原因回传GPT，创建新候选与新轮次。默认最多3轮，重复同一阻塞、超预算或依赖缺失时停止并报告。
- acceptance_passed：检查当前SHA与全部通过记录一致，生成交付清单和文件哈希。
- heartbeat与job_exited：记录进度与最终状态；进程存在不表示测试通过。15分钟定时器的部署范围须另行确认，不能认为画出钩子就已自动运行。

钩子只触发已授权动作，不在提交或测试事件中自动推送GitHub、修改权限或无限重试。项目内数据交给外部模型前沿用用户指定的共享范围；配置不保存密钥。

## 与Roofline分析配合

实现者可分别完成数据流记录、数值核对与图表整理。验证者检查Roofline的N/Q/T是否同一任务、峰值是否有来源、busy是否误当有效计算、接口读写带宽是否重复相加。GPT汇总问题并决定下一轮修改；最终报告保持软件参考、RTL/BFM、板级结果的边界。

## 本次交付的状态

本次增加的是技能说明和协作流程图，未执行图中五类模型的联合运行，也未部署自动调度服务。实际模型调用必须由已授权且可用的适配器完成，使用记录中的真实模型ID；不得把角色设计写成已完成的模型评审。

角色和事件示例见[协作合同](references/workflow.md)。Gemini名称与API标识参照[Google官方模型表](https://ai.google.dev/gemini-api/docs/models)：gemini-3.8-flash、gemini-4-argon。GPT、DeepSeek与Claude的具体版本由实际执行配置记录，不擅自固定。用户已明确Cloud意指Claude。
