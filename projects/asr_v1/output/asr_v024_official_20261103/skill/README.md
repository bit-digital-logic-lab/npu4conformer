# 可复用证据审计技能包

本目录是竞赛随附技能包，不是 PYNQ Overlay，也不声明已获得通用 PYNQ Skill 加分。
适用于具有二进制定长结果、独立参考或互斥耗时分区的加速器项目。Python 3.10 及以上，仅用标准库，不依赖本项目板卡、串号、模型或操作系统路径，不访问硬件。

## 1 数值结果比对

从工作目录根执行

    python skill/audit_evidence.py compare skill/examples/reference_f32.bin skill/examples/equal_f32.bin --dtype f32 --count 4

先声明 dtype 与元素总数，再逐元素检查。支持 f32、f64、i32、i64 小端数据；两个文件都必须具有精确字节长度；NaN 和无穷一律失败。容差为 abs(actual-reference)<=atol+rtol*abs(reference)，默认严格比较。成功退出码0，失败退出码1，标准输出为一份JSON。

来源观察：旧式 zip 配对若不先检查长度，会遗漏多余或截断的结果；使用浮点容差而忽略非有限值也可能产生错误结论。本包将长度和有限性作为进入比对的前提。设计参考成熟数值测试接口的显式容差方式，不额外安装依赖或复制库代码。

失效条件：参考数据本身不可信、端序或张量布局未统一、输出必须按硬件时钟逐拍比较、复数/稀疏/压缩格式尚未解包。脚本不构造算法黄金参考，不验证参考的独立性，也不将输出一致等同整机完成。

## 2 耗时分区校验

    python skill/audit_evidence.py partition skill/examples/board_partition.json

输入含 total_seconds、disjoint_parts 数组及 excluded_overlaps 说明。各互斥项都用秒，名称不可重复，数值须有限且非负，总和在数值容差内等于总时长。输出每项百分比，重叠区间只列为说明，不加进总和。

来源观察：本项目 submit_and_wait 已包含 PL 图执行，直接把两者求和会重复计时。本包的样例来自已保存的插桩原始记录。脚本只检验已声明分区的和、单位契约及合法性，互斥性必须由测点设计证明。秒、周期、服务时间与墙钟时间不能在没有转换或说明时混算。

## 已验证的效果

验证见 report/skill_validation.json：相同数据通过；截断、额外元素、超差、NaN、无穷被拒绝；容差内扰动通过；错误总和、重复名称与负耗时被拒绝。本项目原版与插桩输出的20992个f32值也逐项相同。该一致性案例不是独立算法黄金参考。

## 迁移步骤

在其他工程中先形成独立参考和输出格式契约，修改命令的路径、dtype、count与容差。把该工程的测点映射成互斥秒数分区，并明确哪些区间重叠。先运行相等与故障注入样例，再处理真实结果。本包未进行第二块板或陌生团队迁移验收，不能据此宣称跨板实测成功。
